# 安全政策

## 支持范围

| 组件 | 是否受理 |
|---|---|
| 浏览器扩展（Chromium / Firefox）当前版本 | 是 |
| 本机 Python 服务（`../server`，端口 11436 / 11437） | 是 |
| 旧版本扩展 | 否，请升级后再报 |

## 报告方式

**请不要开公开 issue 讨论安全漏洞。** 请通过 GitHub 的
"Report a vulnerability"（Security Advisory）私下提交，并附上：

- 影响的版本与组件
- 复现步骤
- 影响范围（是否可读取其他站点的图片、是否可外发数据、是否可读取 API Key 等）

## 本项目的攻击面（自查清单）

如果你在做安全审计，以下是这个扩展特有的、值得优先看的地方：

1. **本机服务监听范围**
   `../server` 的 OCR 与翻译服务默认监听 `127.0.0.1:11436` 与 `127.0.0.1:11437`，
   不应对外网开放。若发现其绑定到 `0.0.0.0` 或可被局域网访问，请报告。

2. **API Key 的存储与传输**
   用户为云端 LLM 配置的 API Key 保存在扩展存储中，只发送给用户自己配置的服务地址。
   任何把 Key 发往未配置第三方、或写入日志的行为都属于漏洞。

3. **日志隐私**
   扩展有两条独立日志通道：
   - 事件流：POST 到本机服务的 `/log/events`
   - 扩展本地诊断日志：保存在扩展存储，由弹窗导出

   两条通道是否记录**原文 / 译文**由独立开关控制，**默认关闭**。
   若发现默认即记录原文译文、或开关失效仍落盘，请报告。

4. **页面 DOM 写入**
   扩展不应往宿主页面的 DOM 写入内部状态。架构检查会拦截这类写入
   （见 `scripts/check-extension-architecture.mjs`）。

5. **远程代码加载**
   发布构建不应从远程加载可执行代码。这条由
   `scripts/check-release-boundaries.mjs` 与 CSP 共同保证。

## 已知的非漏洞

以下行为是设计如此，不算安全问题：

- 本机服务未做鉴权——它只监听回环地址，且假设本机用户可信
- 扩展需要读取页面图片的权限才能翻译
- 事件流落盘在本机 `logs/` 目录，不上传

## 模型资产的许可证合规（非安全，但同属发布阻断项）

`packages/model-manifest/publication-policy.json` 中标记为 `blocked` 的模型存在
许可证冲突或来源记录不全。这不构成安全漏洞，但会阻断分发。
相关疑问请在 issue 中讨论。
