### 2.1 Step 14a 的捕获源：主世界 → 内联脚本（改）

- 旧口径：主世界 XHR 钩捕获请求侧形态（端点/Content-Type/showkey）+ `site-globals` 读 showkey。
- 现状：**当前基线零主世界**（奥卡姆审查 `10edd48` 删除，当时零消费者）。
- 新口径：
  - **showkey**：从页面**内联 `<script>` 文本提取**。真机探针实录（`dmb-probe-report.json` calls
    数组）坐实 showkey 以 JSON 字面量内嵌在页面里：
    `api_call({}, '{"method":"showpage","gid":…,"imgkey":"…","showkey":"k67kmy7anu9"}', …)`。
    提取器同时认 JSON 形态（`"showkey":"…"`）与赋值形态（`showkey = '…'`）。
  - **端点**：推导值（归档真机捕获同值）：exhentai → `https://s.exhentai.org/api.php`；
    e-hentai → `https://api.e-hentai.org/api.php`。
  - **请求形态**：照归档真机已验证实现（dispatchOk=4 / dispatchFail=0）原样移植：
    POST JSON 体 `{method:'showpage', gid, page, imgkey, showkey}`、带凭据、响应 JSON 含 `p` 字段。
  - **备选（本批不启用）**：background `webRequest` 被动捕获 requestBody（需加 `webRequest` 权限）。
    仅当真机证明内联提取失败（遥测 `showkeyFound:false`）时再上。
- 随之取消：`m4json:<pageKey>` 持久化（唯一消费者是冻结的 C1 喂槽）→ showpage JSON 只入**内存 Map**。

### 2.2 Step 14b 产物落点：落盘 → 内存（改）

- 旧口径：「产物写 `writeTranslationCache`」。
- 现状：**译图落盘已关闭**（`TRANSLATION_CACHE_PERSISTENCE_ENABLED=false`，2026-10-03 用户拍板：

  到达还原走的正是同一层 —— 预取写、到达读，天然闭环。

### 2.3 取图通道：小实验降级为真机验的一部分（改）

- 旧口径：14b 开工前先做「hath.network 跨域 + credentials/referer」小实验。
- 现状：管线 `remote-image` 源由 **background 下载**（`host_permissions: <all_urls>` 已具备，
  `imageDownloader` 处理 referrer），与手点翻译同一条路 —— 手点翻译真机一直能取图，
  说明通道本身通。预取若被图床拒（签名/ referer），失败会如实进遥测，届时再上 DNR / offscreen 方案。

### 2.4 Step 14c 到达还原：生产代码改不动了，降级为测试钉死（改）

- 旧口径：守卫从「每 key 每生命周期一查」改「每 key 每次挂载一查」+ pageshow bfcache 释放。
- 现状：v0.2.0 删除式简化后，**restore = 纯内存同步查、无守卫**；落盘读取已移出关键路径
  （每会话每页至多一次的后台预热，且现已空转）。旧缺口（"到达时 miss、预取完成后回访不再查"）

- 新口径：本步只做**测试钉死**两个场景：① 到达时预取在跑 → 完成即贴（含画框）；
  ② 到达时预取已完成 → 内存直贴。bfcache `pageshow` 补 sync 已在 v0.2.0 基线里（保留）。

## 4. 风控与停止条件（不变，重申）

- showpage 请求：串行泵、最小间隔 250ms（M3b 参数）、窗口深度 4、known/pending 去重。
- 翻译任务：调度器并发恒 1（16GB 显存约束）。
- 直连连续失败 ×3 且成功为 0 → **熔断**（本次文档生命周期不再发请求），遥测可见原因。
- 真机停止条件：出现一次 `Excessive request rate` → 停（调间隔）；行为与未装扩展不一致 → 停。
- kill switch：`content/index.ts` 的 `PREFETCH_ENABLED = false` 一键归零。
